# LoftDesk v4.7 database plan

## Cel
Przejść z v3 (`user_id` isolation) do v4.7 (`company_id` + `company_members`) bez wyłączania działającej aplikacji.

## Kolejność
1. Uruchom `001_multi_tenant.sql` i `002_rls_policies.sql`.
2. Uruchom `005_multi_tenant_backfill.sql` jako szkic / backup notes.
3. Uruchom `006_company_onboarding.sql` aby dodać funkcję bootstrapu i view statusu.
4. Uruchom `seed.sql` w środowisku lokalnym lub staging, żeby utworzyć companies/company_members z istniejących profiles.
5. Zweryfikuj, że `company_id` został uzupełniony w `clients / projects / cost_estimates / invoices / contracts`.
6. Dopiero potem odpal `007_full_domain_rls.sql` i `008_company_invitations_and_storage.sql`.

## Zasada bezpieczeństwa
Najpierw backfill, potem zaostrzenie RLS. W przeciwnym razie część rekordów stanie się niewidoczna dla użytkowników, bo będzie miała `company_id = null`.

## Deploy strategy
- staging branch z v4.7
- migracje SQL
- smoke tests z `docs/v4.7-test-matrix.md`
- dopiero potem produkcyjny cutover
