# LoftDesk v4.6 security and gating notes

## Co zostało uszczelnione
- osobne reguły dla `feature access` i `action permissions`
- jawne blokady dla modułów: Billing, Admin, KSeF, Team, Portal
- jawne blokady dla akcji CRUD i workflowów w UI
- route-level access notice zamiast pustych ekranów lub przypadkowych błędów

## Bridge danych
`dataScope.ts` rozróżnia dwa tryby:
- `multi-tenant` -> filtracja po `company_id`
- `legacy` -> filtracja po `user_id`

Dzięki temu v4 może działać równolegle z istniejącym schematem i jednocześnie być gotowy na docelową migrację `company_members / companies`.

## Co nadal zostaje po stronie backendu / RLS
- ostateczne wymuszenie ról w bazie
- polityki `INSERT/UPDATE/DELETE` dla każdej tabeli
- audit logi i service functions
- rate limiting i walidacja wejścia dla Netlify Functions

UI gating w v4.6 nie zastępuje RLS, ale usuwa klasę błędów typu: *użytkownik widzi akcję, której nie powinien wykonać*.
