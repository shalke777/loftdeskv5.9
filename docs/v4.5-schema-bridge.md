# v4.5 schema bridge

## Obecny schemat v3 / legacy
`schema.sql` opiera się głównie o:
- `profiles`
- `clients`
- `projects`
- `cost_estimates`
- `cost_estimate_items`
- `invoices`
- `invoice_items`
- `contracts`

Wszystkie główne rekordy są spięte przez `user_id`, a nie przez `company_id`.

## Jak v4.5 to mostkuje
### Tryb demo
- pełne `company_id`
- `company_members` zasymulowane w `demoDb.users`

### Tryb Supabase / legacy
- sesja użytkownika rozwiązywana przez `auth.getUser()`
- profil i plan przez `profiles`
- CRUD modułów działa nadal po `user_id`
- wynik zwracany do UI jest mapowany już do modelu v4 (`company_id`, role, plan, company name)

## Co jeszcze trzeba zrobić, żeby dokończyć przejście
1. wprowadzić `companies`
2. wprowadzić `company_members`
3. dodać `company_id` do tabel domenowych
4. zrobić backfill na podstawie istniejącego `profiles.id -> company_id`
5. przełączyć RLS z `user_id = auth.uid()` na `company_id = my_company_id()`
6. dopiero wtedy pełny multi-user będzie natywny, a nie mostkowany

## Wniosek
v4.5 jest przygotowane na migrację krok po kroku:
- **dziś** może pracować na legacy schema
- **jutro** może wejść w pełny multi-tenant bez przepisywania UI od nowa
